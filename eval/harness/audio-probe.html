Audio probe — /speech/uploadVoice

Answers one question: can a browser recording reach Google STT through the endpoint the uni-app client uses today? The endpoint decodes MP3 via mp3spi, and browsers do not record MP3 — so this measures how much work the eval harness actually needs.

0 · Setup

Serve this page on port 8081 — the backend's CORS list allows it. From the repo root: python3 -m http.server 8081 --directory eval/harness, then open http://127.0.0.1:8081/audio-probe.html. Backend must be running on 8080.

Backend: 
checking browser support…

1 · Record as the browser prefers (MediaRecorder)

What MediaRecorder produces natively — WebM/Opus in Chrome, MP4/AAC in Safari. This is what the harness would send if written the obvious way.

2 · Record as 16 kHz mono WAV (Web Audio)

Captures raw PCM and wraps it in a WAV header at exactly the sample rate Google STT wants (16 kHz, mono, LINEAR16) — the same format recognizePcm already builds internally. If the server accepts this, no transcoder is needed anywhere.

3 · Verdict

Run both tests above.
